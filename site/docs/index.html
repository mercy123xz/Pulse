How Pulse is made

Pulse is a native Windows app written in Rust. There's no web browser hidden inside it: every button, list and cover is drawn by the app itself, straight onto your graphics card.

  • Interface: egui, a toolkit that redraws the window from the app's current state, so what you see always matches what's happening. Drawing goes through wgpu and DirectX 12. On PCs without a working graphics driver, it falls back to Windows' built-in software renderer, so Pulse opens anywhere.
  • Audio: rodio plays the sound and Symphonia decodes MP3, AAC/M4A, FLAC, WAV and Ogg. The equalizer, fades and the rest are Pulse's own code, applied to every sample.
  • Networking: ureq with rustls for secure connections, with no system libraries needed.
  • Everything slow happens off to the side. Searches, downloads, decoding and lookups run on background threads, so the window never freezes while something loads.

The result is one pulse.exe with the Visual C++ runtime and the icon built in. It needs no extra DLLs, and the installer is under 10 MB.

From code to download

Every version you download is built the same way, by machines, from the code in the GitHub repository. Nobody builds a release by hand.

  1. ChangeNew work lands on a separate branch first and is tested there.
  2. BuildEvery push starts a Windows build on GitHub Actions: the release pulse.exe and the test suite.
  3. CheckThe build makes sure the app needs no extra DLLs and that its icon is embedded. A failure stops everything.
  4. PackageInno Setup wraps the app into PulseSetup-x.y.z.exe, an installer that needs no administrator password.
  5. ReleaseWhen the main branch has a new version number, a GitHub release is published with just the installer attached.
  6. WebsiteThis site lives in the repo's site folder and is published to GitHub Pages on every change. Its download button always fetches the newest installer.

Versions follow major.minor.patch: the last number for fixes and small additions, the middle one for bigger features. The changes in each version are listed on its release page.

How a song plays

When you press play, a few things happen in a couple of seconds:

  1. Song infoThe title, artists, album, length and cover come from Deezer's catalog.
  2. Finding the audioPulse searches YouTube with yt-dlp and scores the results by title, artist and length, so it picks the right recording, not a live version or a cover.
  3. Remembering itThe match is saved, so the next time you play that song Pulse skips the search.
  4. StreamingThe first megabyte is fetched in order so music starts fast. The rest arrives in 1 MB pieces, three at a time, which is much quicker on most connections.
  5. Decoding and effectsThe audio is decoded, then the equalizer, mono and fades are applied.
  6. Getting ready for the next oneWhile a song plays, the next one is found and opened ahead of time, so songs change without a wait.

Two decks, like a DJ

The audio engine has two players. Gapless playback queues the next song on the same player, so it starts on the exact sample the last one ends. Crossfade and automix start the next song on the second player and fade between the two. Automix also listens for silence at the end of a song and starts the next one where the music actually stops.

The first song

YouTube playback needs two free tools, yt-dlp and Deno (about 70 MB together). Pulse downloads them the first time you play a song, from their official GitHub releases, and checks each against its published checksum before using it. After that, Pulse checks once a day for a new yt-dlp and updates it in the background, so playback keeps working when YouTube changes.

Pulse only plays full songs. If YouTube can't play one, Pulse tells you and moves on; it never falls back to a 30-second preview.

Where music info comes from

Charts, search results, artist pages, albums, playlists and covers come from the free Deezer API. No account or key is needed.

  • Every credited artist. A song's main artist and its featured artists come from its credits, so a track released under a label or collective still shows the artists who perform on it. Each name opens that artist's page.
  • Most popular songs. Artist pages show the ten most popular songs, ordered by Deezer's popularity score.
  • Whole albums and playlists. Long albums and playlists are fetched page by page until every song is there, so playing one queues all of it, in order.
  • Missing covers are looked up in the iTunes catalog. YouTube view counts come from YouTube's public numbers.
  • Lyrics and annotations aren't part of this version.

Asking politely

Deezer allows about 50 requests every 5 seconds. Pulse keeps recent replies for ten minutes so the same question isn't asked twice, and when Deezer says it's busy, Pulse waits and tries again instead of showing an error. When you rest the pointer on an album or artist card, Pulse loads that page in the background (two at a time at most), so it opens instantly when you click.

Sound and effects

  • Equalizer: six bands (60 Hz to 15 kHz), each a peaking filter, with presets and your own saved settings. When bands are boosted, the overall volume is lowered a little so loud songs don't distort.
  • Crossfade: up to 10 seconds of overlap between songs.
  • Gapless: no silence between songs that are meant to run together.
  • Automix: trims silence at the ends of songs and blends into the next.
  • Mono: both speakers get the same sound, for one earbud or a single speaker.

All of these work the same on streamed songs, downloaded songs and the files in your Music folder.

Staying light

A music player runs for hours next to everything else on your PC, so Pulse tries to use as little as it can:

  • No browser engine and no background services. When you close Pulse, it's gone.
  • Network requests are kept to what a page needs, and repeated ones are answered from memory.
  • Work that takes time (searching, streaming, decoding, lookups) never runs on the thread that draws the window.
  • Moving backgrounds and other motion can be turned off in Settings, with Reduce motion or Moving background.
  • It prefers the battery-friendly graphics chip on laptops with two.

Making a theme

Pulse comes with five themes: Default, Blossom, Dreary Mono, Lunar and Aurora. Each has a dark and a light version. To make your own, open Settings → Themes and choose Make a copy of one to start from, or create a folder yourself:

%APPDATA%\pulse-player\themes\My Theme\
    color.ini    colors (one section per color scheme)
    user.css     shapes and spacing
    theme.toml   name and layout

Any of the three files can be left out. Pulse reloads a theme the moment you save one of its files, so you can watch changes as you make them.

color.ini

Colors use Spicetify's names, so Spicetify color schemes work as they are. Missing keys are worked out from the others.

[Dark]
main               = 0b0b0e   ; background
sidebar            = 0f0f13
player             = 0f0f13   ; player bar
card               = 16161b
highlight          = 1d1d24   ; hovered rows
highlight-elevated = 24242d   ; selected rows
border             = 2c2c36
text               = ededf1
subtext            = 9696a4
text-faint         = 80808e
button             = 7c3aed   ; accent: buttons and sliders
button-active      = a78bfa   ; accent for text and icons

Pulse checks that text stays readable: when a color pair falls below the WCAG AA contrast level, Settings → Themes shows it under Theme notes.

user.css

A small part of CSS for named parts of the window:

PartsProperties
.sidebar .header .hero .player-bar .card .track-row .play-button background, color, border, border-color, border-width, border-radius, padding, font-size, font-weight, text-transform: uppercase 
:root { --radius-sm: 8px; --radius-md: 12px; --radius-lg: 16px; }
.card { background: var(--spice-card); border-radius: 14px; }
.play-button { background: var(--spice-button-active); color: var(--spice-main); }

Colors can be #rrggbb, rgb(), rgba() or var(--spice-KEY). Anything Pulse doesn't support is skipped, and Settings → Themes lists what was skipped.

theme.toml

name = "My Theme"
author = "Me"
description = "What it looks like"

[layout]
sidebar = "full"           # or "icons"
hero = "banner"            # or "fullbleed": a full-width artist photo
player = "centered"        # or "controls-left"
now_playing_art = "bar"    # or "sidebar-large"
inset = false              # true: the main area floats as a rounded panel
backdrop = false           # true: soft glows in the playing song's colors

With backdrop on, Pulse works out the main color of the playing song's cover (once per song, in the background) and fills the main area with slow-moving glows in that color.

Your data

Pulse has no accounts and no servers of its own. Everything it keeps stays on your PC, in %APPDATA%\pulse-player:

  • your likes, playlists, recently played songs, profile and settings
  • your themes
  • songs you download for offline listening (in offline; Settings → Storage lets you choose another place)
  • yt-dlp and Deno, and a cache of temporary files (Settings → Storage shows its size and can clear it)

Pulse also plays the music files in your Windows Music folder if you turn on Show Local Files in Settings. The only places Pulse talks to are the ones it gets music from: Deezer for song info, YouTube for audio, iTunes for missing covers, and GitHub when it fetches or updates its playback tools. Uninstalling keeps your folder, so reinstalling picks up where you left off; delete the folder to remove everything.

Your playlists can be shared as a one-line code that contains just the list of songs. Nothing is uploaded: the code itself is the playlist.

Building it yourself

You need Rust. On Windows, its installer offers to set up the Visual Studio C++ Build Tools too; say yes.

git clone https://github.com/mercy123xz/Pulse.git
cd Pulse
cargo run --release

The first build takes a few minutes; the app ends up at target\release\pulse.exe. Run the tests with cargo test. To make the installer, install Inno Setup and run:

iscc /DAppVersion=1.0.0 installer\pulse.iss

If something goes wrong

"Windows protected your PC"

Windows shows this for any new app that isn't signed with a paid certificate. Click More info, then Run anyway. You'll only see it once.

The first song takes a while

Pulse is downloading its playback tools (about 70 MB, once). The player bar shows the progress. After that, songs start in a few seconds.

A song won't play

YouTube may not have a full version of it, or YouTube changed something and yt-dlp hasn't caught up yet. Pulse updates yt-dlp daily, so trying again later often works. Pulse skips to the next song after a failure.

The window flickers or stays blank

Turn off Settings → Compatibility → Enable hardware acceleration and restart Pulse. It will draw with Windows' software renderer instead.
